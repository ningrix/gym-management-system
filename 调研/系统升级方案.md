# 系统升级方案（v2）

> 依据《竞品调研与优化提升方案》《算法与数据能力调研报告》制定。原则：**与现有代码兼容**——只增表、增列、增接口，不改既有字段语义；旧数据无需迁移即可运行。

## 一、功能调整

| 编号 | 功能 | 参照 | 优先级 |
|---|---|---|---|
| F1 | 自主训练到店记录（区分团课签到与自助入场） | 光猪圈数据回传 | P0 |
| F2 | 预约超时自动标记 NO_SHOW | 行业口径（出勤率真实性） | P0 |
| F3 | 候补队列（满员排队、取消自动递补） | 乐刻课程包/付费排队 | P1 |
| F4 | 三级取消阶梯 + 月度临时取消额度 | 乐刻 6h/3–6h/3h 阶梯、超猩每月额度 | P1 |
| F5 | 旷课熔断（一周 NO_SHOW≥2 → 本周限约 1 节） | 乐刻旷课熔断 | P1 |
| F6 | 到期 + 流失双预警 | Mindbody Autopay 催收、RFM | P1 |
| F7 | 教练课时结算单 | Mindbody Payroll、三体提成 | P1 |
| F8 | 团课选位（自动分配最小空闲位置号） | Mindbody Pick-a-Spot | P2 |

## 二、数据结构更新

| 表/列 | 变更 | 说明 |
|---|---|---|
| 新表 `checkin_log` | id, member_id, checkin_type(SELF/COURSE), ref_id, create_time | 到店记录；团课签到同时写入一条 SELF 记录，保证到店率口径完整 |
| 新表 `waitlist` | id, schedule_id, member_id, member_card_id, status(WAITING/PROMOTED/CANCELLED), enqueue_time, create_time | 候补队列；唯一索引 (schedule_id, member_id) 防重复排队 |
| 新表 `member_alert` | id, member_id, alert_type(DUE/CHURN), content, status(OPEN/HANDLED), handle_note, create_time, handle_time | 双预警落库，可回填处理结果 |
| `course_schedule` + `position_total` | INT NOT NULL DEFAULT 0 | 选位总数（0=不选位）；容量仍由 capacity 控制 |
| `reservation` + `position_no` | INT NULL | 选中的位置号 |
| `reservation` + `cancel_type` | VARCHAR(20) NULL | FREE（>6h 免责）/ QUOTA（2–6h 计临时取消） |
| 兼容性 | 全部为新增，不改既有列 | 旧数据插入默认值即可运行；H2 与 MySQL 脚本同构 |

## 三、接口变更

| 接口 | 类型 | 说明 |
|---|---|---|
| POST /api/reservations | 行为变更 | 满员返回 409 并提示可排候补；capacity>0 的课自动分配最小空闲 position_no；次卡占坑校验（已上线） |
| PUT /api/reservations/{id}/cancel | 行为变更 | 三级阶梯：>6h FREE；2–6h 计当月临时取消（≥3 次拒绝）；<2h 拒绝。取消成功后自动递补候补第一名 |
| POST /api/reservations/{scheduleId}/waitlist | 新增 | 满员排候补（校验未重复、卡有效） |
| DELETE /api/reservations/waitlist/{scheduleId} | 新增 | 退出候补 |
| GET /api/reservations/waitlist/my | 新增 | 我的候补记录 |
| GET /api/member-alerts | 新增 | 当前登录会员的到期/流失预警 |
| PUT /api/member-alerts/{id}/handle | 新增 | 管理员回填处理结果 |
| GET /api/member-alerts | 新增（管理端） | 全馆预警列表（含会员姓名） |
| POST /api/checkin-logs | 新增 | 前台代录自助入场 |
| GET /api/checkin-logs/my | 新增 | 本人到店记录 |
| GET /api/reports/coach-settlement | 新增 | 教练课时结算明细（按月，含课时费合计） |

## 四、模块重构

1. **ReservationService.reserve** 拆出两个私有方法：`occupySeat`（名额条件更新）与 `assignPosition`（选位分配），预约/候补递补共用；
2. **新增 `SweepService`**：`@Scheduled` 定时任务——课程结束 30 分钟后把 BOOKED 置 NO_SHOW、同步排课状态为 FINISHED、每日 02:00 生成到期/流失预警；
3. **`CourseScheduleService.effectiveStatus`**（已上线）继续作为状态推导的单一事实源；
4. 统计口径：`ReportService` 到店类指标改从 `checkin_log` 计算。

## 五、不做与延后

- 协同过滤推荐、实时动态定价、自动排课优化器、机器学习流失预测（数据量不支持，见算法报告）；
- 会员端小程序/H5（视觉方向 A 预留）；
- 在线支付与短信推送（需第三方资质）。

## 六、验收标准

1. 接口回归（smoke_test.py）全部通过，新增候补/取消阶梯/选位/结算用例通过；
2. 三角色端到端（e2e.js）全部通过，0 控制台错误、0 失败请求；
3. 取消后重约、次卡超订、名额满员三处历史缺陷不再复现；
4. NO_SHOW 任务在课程结束 30 分钟后正确落库；
5. UI 按"方案 B + #FCC800 强调"规范更新，表格/导航/图表对比改版前后可见差异。
