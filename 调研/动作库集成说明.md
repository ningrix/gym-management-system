# 动作库模块集成说明

## 一、模块定位

健身动作演示来自开源数据集 **exercises-dataset**（Gitee 社区汉化分支），共 1,324 个动作，含中文名（`name_zh`）与中文步骤说明。
它以**独立静态模块**挂载在 `/exercises/`，不依赖后端接口、不进入会员系统的前端构建，会员系统只提供一个入口。

## 二、目录与部署

```
<项目根>/
├── exercises-dataset/          ← 外置目录（不打进 jar）
│   ├── index.html              ← 已改为 fetch data/exercises.json（51KB）
│   ├── data/exercises.json     ← 17MB，gzip 后约 2MB
│   ├── images/                 ← 静态缩略图（jpg）
│   ├── videos/                 ← 动图（gif，悬浮/详情加载）
│   ├── LICENSE / NOTICE.md     ← 原始授权与署名
└── gym-management/target/gym-management.jar
```

- 服务映射：`WebConfig.addResourceHandlers` 将 `/exercises/**` 指向该目录，应用启动日志会打印挂载路径。
- 目录缺失时只打印 WARN，不影响会员系统启动（`/exercises/` 返回 404）。
- 自定义位置：`--gym.exercises.dir=file:/data/exercises-dataset/` 或环境变量 `GYM_EXERCISES_DIR`。

## 三、缓存策略（已在 Spring 中实现）

| 路径 | 缓存 | 说明 |
|---|---|---|
| `/exercises/images/**`、`/exercises/videos/**` | `max-age=604800`（7 天） | 文件名带哈希，内容不变 |
| `/exercises/data/**` | `max-age=3600`（1 小时） | JSON 数据 |
| `/exercises/**` | `max-age=300`（5 分钟） | 页面本体，便于更新 |

`application.yml` 已开启 gzip（`server.compression`），17MB 的 JSON 传输时约 2MB。
若前置 Nginx，可直接用 `deploy/nginx-exercises.conf` 由 Nginx 托管，注意 `alias` 与 `location` 末尾都要带 `/`。

## 四、入口

会员端左侧菜单「拓展 → 动作库」，`window.open('/exercises/','_blank','noopener')` 新标签打开，不影响主系统登录态。
菜单项在 `static/js/core.js` 中通过 `external: true, href: '/exercises/'` 声明，模板中 `openExternal(item)` 处理。

## 五、本轮改动

1. **内联数据改为外链 JSON**：原 `index.html` 16.5MB（1,324 条数据内联），改为 `fetch('./data/exercises.json')` 后降到 **51KB**，数据可被浏览器缓存；加载失败时页面顶部给出中文错误提示。
2. **中文与标题**：`<title>` 与侧栏品牌改为中文（健身动作库）；界面词条、筛选值、动作名沿用数据集自带的 `zh` 词条与 `name_zh`，未做二次翻译。
3. **缺失媒体兜底**：图片加载失败时显示灰色占位图标，不再出现浏览器自带的破图符号（`onerror` 必须先绑定再赋 `src`，否则缓存命中时会漏掉事件）。当前 **1324 张 JPG + 1324 个 GIF 已全部就位**（约 139MB），`.git` 目录已删除。
4. **版权署名**：页面底部与侧栏保留 `Gym visual` 署名与跳转链接，`LICENSE` / `NOTICE.md` 原样保留。
5. **响应式**：≤768px 侧栏变顶部面板、卡片两列；≤480px 工具按钮收为图标，已用 390px 设备仿真验证无横向溢出。

## 六、媒体补齐

```bash
python tools/fetch_media_fast.py           # 推荐：走 Gitee raw 通道，24 并发，约 1 分钟补齐图片
python tools/fetch_media_fast.py --all     # 补全部 GIF
```

`fetch_media_fast.py` 直接走 `raw/main/<path>`（带 UA、跟随 302），比逐文件 `git show` 快一个数量级；
`fetch_exercise_media.py` 为早期的 git 按需拉取方案，保留作备用。媒体已全量就位，日常无需再跑。
